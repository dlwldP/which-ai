# 결정 사항

기획서에 정해지지 않은 세부 사항을 J가 확인해서 정한 내용이다. 기획서와 충돌하면 이 문서를 따른다.

| 날짜 | 항목 | 결정 |
| --- | --- | --- |
| 2026-10-19 | `platforms` 값 | `web` / `ios` / `android` / `windows` / `mac` 중에서 고른다. |
| 2026-10-19 | "휴대폰에서 쓸 거예요" 조건 | `ios` 또는 `android` 앱이 있는 툴만 남긴다. 웹사이트만 있는 툴은 제외한다. |
| 2026-10-19 | 결과 0개일 때 조건 완화 | 휴대폰 조건을 먼저 빼고, 그래도 0개면 무료 조건도 뺀다. **보안 조건은 빼지 않는다.** 그래도 0개면 "조건에 맞는 툴이 아직 없어요"라고 안내한다. 한국어 중요 조건은 점수에만 영향을 주므로 완화 대상이 아니다. |
| 2026-10-19 | 추천 이유 추가 문장 | 적합도 2 → "이 일에 잘 맞는 툴이에요", 적합도 1 → "이 일에도 쓸 수 있어요", 무료 → "무료로 시작할 수 있어요". 적합도 문장이 항상 하나 붙으므로 이유가 0개인 카드는 없다. |
| 2026-10-19 | 툴 수 상한 | 적합도 1점 이상인 툴이 목적당 5개를 넘거나, 전체 툴이 40개를 넘으면 데이터 검사가 실패한다. |
| 2026-10-19 | `price.billing` | `monthly` / `yearly` / `unknown` 중 하나. |
| 2026-10-19 | `price.free` | `true` / `false`만 허용한다. 무료 여부를 확인 못 한 툴은 아직 넣지 않는다 (기획서 7장 "확인 안 된 툴은 넣지 않는다"). |
| 2026-10-19 | `start_steps` | 정확히 3개. |
| 2026-10-19 | 화면 디자인 | 따뜻한 종이 느낌: 아이보리 배경, 먹색 글자, 얇은 테두리 카드(그림자 없음), 테라코타 포인트, 제목만 명조(Noto Serif KR), 본문 Pretendard. (처음엔 Awscal 톤이었다가 바꿈) |
| 2026-10-19 | 화면 구조 | `index.html` 한 페이지. 주소로 단계를 나눈다: `#/` 홈, `#/p/<목적>` 조건 선택, `#/p/<목적>/result?조건` 결과. 뒤로 가기·링크 공유가 된다. |
| 2026-10-19 | 예시 데이터 | 주소에 `?demo`가 있을 때만 `data/demo-tools.json`(지어낸 툴)을 쓰고, 화면 맨 위에 "예시 데이터예요" 띠를 띄운다. 그 외에는 `data/tools.json`만 쓴다. |
| 2026-10-19 | 추천 결과 배치 | 카드를 가로로 나란히 놓는다. 휴대폰은 옆으로 넘기고(한 장씩 멈춤, 아래 점으로 위치 표시), 넓은 화면(900px 이상)은 3개를 한 번에 보여준다. 따로 있던 비교표는 없애고, 비교 항목을 카드마다 같은 순서·같은 높이로 넣는다. |
| 2026-10-19 | "뭘 해야 할지 모르겠어요" 바로가기 | P01 질문하고 글 쓰기, P03 긴 문서·PDF 요약, P07 번역. |
