# AI 뭐 써? 기획서

> 하고 싶은 일을 고르면 맞는 AI 툴 2~3개를 비교해서 추천해주는 비개발자용 선택 도우미
> 버전: v0.1 (MVP 기획) · 작성: 2026-10-19 · 시리즈: "AWS 얼마야?"의 자매 프로젝트

> 이 문서에서 정하지 않은 세부 사항은 [decisions.md](decisions.md)에 정리했다.

---

## 1. 한 줄 정의

"회의록 정리하고 싶은데 뭐 써?"에 답하는 사이트. **목록을 보여주지 않고**, 목적과 조건을 고르면 툴 2~3개를 이유와 함께 비교해준다.

## 2. 문제와 타깃

| 항목 | 내용 |
| --- | --- |
| 문제 | AI 툴이 너무 많아서 비개발자는 어떤 일에 뭘 써야 하는지, 무료로 되는지, 회사 자료를 넣어도 되는지 판단하기 어렵다. 기존 AI 디렉터리는 수천 개를 나열만 해서 오히려 고르기 힘들다. |
| 타깃 | 직장인, 대학생, 소상공인, 부모님 세대 등 AI를 써보고 싶은 비개발자 |
| 차별점 | ① **목록이 아니라 선택 도우미**: 목적 → 추천 2~3개 ② **추천 이유를 문장으로** 표시 ③ **보안·학습 정책**을 비교 항목으로 기본 노출 ④ **"시작 방법 3단계"**로 실제 사용까지 안내 ⑤ 모든 정보에 **확인 날짜** 표시 |

## 3. 범위

### MVP에 포함

- 목적 10개 × 툴 30개 안팎의 큐레이션 데이터
- 추천 흐름: 목적 선택 → 조건 선택 → 추천 2~3개 비교
- 툴 상세: 가격, 무료 한도, 한국어 품질, 데이터 학습 정책, 시작 방법 3단계, 주의사항
- 용어집 ("프롬프트", "토큰", "무료 크레딧" 등)
- 정보 신선도 표시 (`last_verified`) + 오래된 항목 "확인 필요" 배지
- 변경 이력 페이지
- 다크모드, 모바일 대응

### MVP 이후

- 사용자가 "정보가 틀려요" 제보 (GitHub Issue 링크로 시작), 목적별 프롬프트 예시, 영어·일본어 버전

### 절대 하지 않을 것 (Non-goals)

- **GitHub 레포, 설치형·개발자용 도구** (터미널·API 키가 필요한 것은 다루지 않음)
- ~~툴 수 늘리기 경쟁 (목적당 최대 5개, 전체 40개 상한)~~ → 2026-10-22 변경: 상한을 없애고 웬만한 AI 툴은 모두 넣는다. 대신 화면은 여전히 2~3개만 추천하고 나머지는 접힌 "다른 후보 더 보기"에 둔다 (홈에 목록을 두지 않는 원칙은 그대로)
- 런타임 LLM 호출, 서버, 회원가입 (운영비 0원 유지)
- 제휴 링크·광고로 추천 순위를 바꾸는 것

## 4. 설계 원칙

1. **추천은 규칙으로**: 사이트에서 LLM을 부르지 않는다. 큐레이션 점수와 조건 필터로 결정론적으로 추천하고, 같은 입력이면 항상 같은 결과가 나온다.
2. **이유 없는 추천 금지**: 추천 카드마다 "왜 이걸 추천했는지" 문장이 최소 1개 있어야 한다. 데이터에서 자동 생성한다.
3. **모르면 모른다고 표시**: 확인 안 된 값은 빈칸이 아니라 "확인 필요"로 표시한다. 90일 넘게 확인 안 된 항목은 배지를 단다.
4. **출처 필수**: 가격·정책 값은 공식 페이지 URL을 `sources`에 남긴다.
5. **쉬운 말**: 화면 문구에 영어 약어와 전문용어를 쓰지 않는다. 불가피하면 용어집 툴팁을 단다.

## 5. 사용자 시나리오

1. **회의록**: 팀장이 "회의 녹음을 정리하고 싶다" 선택 + "회사 자료라 보안 중요" → 학습에 쓰지 않는 옵션이 있는 툴 위주로 2개 추천, 각각 "녹음 파일 올리기 → 요약 버튼 → 공유" 3단계
2. **발표자료**: 대학생이 "PPT 만들기" + "무료만" → 무료 한도 안에서 되는 툴 2개, "무료는 한 달 N장까지" 같은 숨은 제한 경고
3. **영상 자막**: 소상공인이 "유튜브 영상 자막" + "한국어 잘 되는 것" → 한국어 품질 상위 툴 추천
4. **잘 모를 때**: "뭘 해야 할지 모르겠어요" → 많이 쓰는 목적 Top 3 바로가기

## 8. 데이터 설계

### `data/tools.json` (툴 1개 예시)

```json
{
  "id": "gamma",
  "name": "Gamma",
  "url": "https://gamma.app",
  "one_liner": "주제만 쓰면 발표자료를 자동으로 만들어줘요",
  "features": { "P04": ["from_topic", "auto_design", "export_ppt"] },
  "price": {
    "free": true,
    "free_limit": "확인 필요",
    "paid_from_usd": null,
    "billing": "monthly"
  },
  "korean": 2,
  "privacy": {
    "trains_on_input_default": "unknown",
    "opt_out": "unknown",
    "note": ""
  },
  "platforms": ["web"],
  "login": "google | email",
  "start_steps": [
    "사이트에서 구글 계정으로 로그인",
    "'새로 만들기' → 주제 한 줄 입력",
    "디자인 고르고 PPT로 내보내기"
  ],
  "cautions": ["무료 크레딧을 다 쓰면 유료 전환 필요"],
  "sources": ["https://gamma.app/pricing"],
  "last_verified": "2026-10-19"
}
```

| 필드 | 규칙 |
| --- | --- |
| `features` | 목적별로 지원하는 기능 ID 목록 (그 목적의 기능 체크리스트 4개 중에서). 공식 페이지가 그 용도로 직접 소개하는 기능만 넣고, 기능마다 근거 문장을 남긴다. 지원 기능이 없는 목적은 적지 않는다. (2026-10-22 변경: 예전에는 사람이 정하는 적합도 0~3점) |
| `korean` | 1 = 메뉴·결과 모두 영어 위주, 2 = 결과는 한국어 가능, 3 = 메뉴까지 한국어 + 한국어 품질 좋음 |
| `privacy.*` | `yes / no / unknown`. `unknown`은 화면에 "확인 필요"로 표시 |
| `last_verified` | 마지막으로 공식 페이지에서 확인한 날짜. 필수 |

### `data/purposes.json`, `data/glossary.json`, `data/changelog.json`

목적 정의(목적마다 기능 체크리스트 4개: `features: [{ id, label, short }]`), 용어집, 변경 이력. 변경 이력은 `tools.json` 변경 커밋에서 생성한다.

## 9. 추천 로직 (코드, LLM 없음)

```
입력: 목적 P, 조건 { 무료만, 보안 중요, 한국어 중요, 사용 기기 }

1. 후보 = features[P]에 기능이 1개 이상인 툴
2. 필터
   - 무료만      → price.free == true
   - 보안 중요   → privacy.trains_on_input_default == "no" 또는 opt_out == "yes"
   - 사용 기기   → platforms에 포함
3. 점수 = (features[P]의 기능 수) × 10
         + (한국어 중요 ? korean × 4 : korean × 1)
         + (price.free ? 2 : 0)
         - (최종 확인 90일 초과 ? 3 : 0)
4. 상위 3개 (동점이면 이름순), 나머지 후보는 "다른 후보 더 보기"에 같은 순서로. 필터 후 0개면 조건을 하나씩 풀어서 재시도하고
   "무료 조건을 빼면 이런 선택지가 있어요"라고 안내
5. 추천 이유 생성 (템플릿)
   - 기능 문장       → "받아쓰기, 요약 지원 (4개 중 2개)" (켠 조건과 관련된 이유가 없으면 이게 대표 이유)
   - korean == 3      → "메뉴와 결과 모두 한국어로 잘 돼요"
   - 보안 조건 충족    → "입력한 내용을 학습에 쓰지 않도록 설정할 수 있어요"
```

> 보안 중요 조건에서 `unknown` 툴은 추천하지 않는다. 모르는 걸 안전하다고 보여주지 않기 위해서다.
>
> 순서는 좋고 나쁨의 순위가 아니라 "이 일에 필요한 기능을 몇 개 지원하는지"다. 화면에도 그렇게 밝히고, 카드에 순위 번호를 붙이지 않는다.

## 10. 화면 구성

1. **홈**: 큰 질문 "어떤 일을 AI에게 맡기고 싶어요?" + 목적 10개 아이콘 카드
2. **조건 선택**: 토글 4개 (무료만 / 회사 자료라 보안 중요 / 한국어 중요 / 휴대폰에서 쓸 거예요)
3. **추천 결과 (메인)**: 카드 2~3개 나란히
    - 이름, 한 줄 설명, 추천 이유 배지
    - 비교표: 가격, 무료 한도, 한국어, 학습 정책, 사용 기기
    - "이렇게 시작해요" 3단계, 주의사항, 공식 사이트 버튼
    - 하단: "마지막 확인 2026-10-19 · 출처 보기"
4. **툴 상세**: 툴 하나의 전체 정보 + 이 툴을 쓸 수 있는 다른 목적
5. **용어집**, **변경 이력**

## 11. 기술 스택과 배포 (AWSCAL과 동일)

| 영역 | 선택 |
| --- | --- |
| 프론트 | 순수 HTML/CSS/JS, 빌드 없음 |
| 데이터 | `data/*.json` |
| 검증 | JSON 스키마 검사 스크립트 (Node) |
| 테스트 | Node 내장 테스트 러너 (추천 로직, 스키마) |
| 배포 | GitHub Actions → GitHub Pages |
| 자동 점검 | 주간 Action: ① 공식 URL 링크 체크 ② `last_verified` 90일 초과 목록 → GitHub Issue 자동 생성 |

> 가격을 자동으로 긁어오지 않는다. 사이트마다 구조가 달라 깨지기 쉽고, 틀린 값이 자동 반영되는 게 더 위험하다. 자동화는 "확인해야 할 목록을 만들어주는 것"까지만 한다.

## 12. 테스트 기준

| 테스트 | 내용 |
| --- | --- |
| 스키마 | 모든 툴에 필수 필드, `sources` ≥ 1, `last_verified` 날짜 형식 |
| 추천 규칙 | 보안 중요 조건에서 `unknown`·학습 기본 사용 툴이 절대 나오지 않음 |
| 추천 규칙 | 무료만 조건에서 유료 전용 툴이 나오지 않음 |
| 추천 규칙 | 모든 목적에서 조건 없이 최소 2개 추천됨 |
| 추천 이유 | 모든 추천 카드에 이유 문장 ≥ 1 |
| 결정성 | 같은 입력 100회 → 같은 결과 |

## 13. 개발 단계 (바이브코딩 Phase)

| Phase | 목표 | 완료 조건 |
| --- | --- | --- |
| 0. 데이터 | 목적 10개 확정, 툴 30개 공식 페이지 확인 후 `tools.json` 작성 | 스키마 검사 통과, 모든 툴에 출처·확인 날짜 |
| 1. 추천 로직 | `js/recommend.js` 순수 함수 + 테스트 | 12장 테스트 전부 통과 |
| 2. 화면 | 홈, 조건 선택, 추천 결과 | 모바일·데스크톱에서 시나리오 1~4 수동 확인 |
| 3. 상세·부가 | 툴 상세, 용어집, 변경 이력, 다크모드 | 모든 툴 상세 페이지 열림 |
| 4. 배포·자동화 | Pages 배포, 주간 링크·신선도 점검 Action | 일부러 날짜를 오래된 값으로 바꾸면 Issue 생성 확인 |
| 5. 마감 | README, 데이터 기여 가이드, 스크린샷 | 비개발자 3명에게 써보게 하고 피드백 반영 |

> 핵심: **Phase 0이 이 프로젝트의 본체다.** 코드는 단순하고, 가치는 데이터 품질에서 나온다. 바이브코딩에 맡기지 말고 J가 직접 확인해서 채워야 한다.

### Phase별 첫 프롬프트 예시

- **Phase 1**: "CLAUDE.md와 기획서 9장을 읽고 `js/recommend.js`에 추천 함수를 만들어. 입력은 목적 ID와 조건 객체, 출력은 툴 3개와 추천 이유 배열이야. DOM에 접근하지 말고 순수 함수로 만들어. 기획서 12장의 테스트를 `tests/recommend.test.js`에 작성해."

## 14. CLAUDE.md 초안

```markdown
# AI 뭐 써? 작업 규칙
- 기획서: docs/AI뭐써_기획서.md 가 기준이다. 없는 기능은 제안만 한다.
- 절대 금지: data/tools.json의 가격·정책 값을 추측으로 채우는 것. 모르면 "unknown".
- 절대 금지: 런타임 LLM 호출, 서버 코드, 빌드 도구 도입, 광고·제휴 링크.
- 추천 로직은 js/recommend.js 순수 함수에만 둔다. 화면 코드에서 점수를 계산하지 않는다.
- 화면 문구는 비개발자 기준 쉬운 한국어로 쓴다. 영어 약어 금지.
- 수정 후 `node --test`를 실행하고 결과를 보고한다.
```
